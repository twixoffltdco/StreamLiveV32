# GitHub-деплой для VK-конструктора (dev.vk.com аналог)

## Что было в архиве ДО этого
`developers.php` + `oauth2/authorize.php` + `oauth2/token.php` — OAuth2-провайдер ("войти через наш аккаунт"),
`services.php` с модалкой согласия — но **только для OAuth-приложений**, без какого-либо GitHub API.

## Что добавлено сейчас
- `github_connect.php` — подключение GitHub по Personal Access Token (проверяется живым запросом к api.github.com, токен шифруется AES-256 перед записью в БД)
- `github_deploy.php` — список репозиториев токена → выбор репо/ветки → синхронный деплой: скачивание zip через codeload.github.com → распаковка → поиск index.html
- `s.php` — просмотр задеплоенного сервиса: **модальное окно согласия** ("хотите открыть, вы можете передать данные, согласны на риск?"), как ты просил, плюс iframe с `sandbox` (без `allow-same-origin` — иначе чужой JS получил бы доступ к кукам твоего сайта, раз сервисы на том же домене)
- `services.php` — теперь показывает и OAuth-приложения, и задеплоенные GitHub-сервисы в одном каталоге, с единой модалкой согласия под каждый тип

## Обязательные шаги перед использованием

**1. Ключ шифрования токенов.** В `config.php` добавить:
```php
define('APP_ENCRYPTION_KEY', 'вставь_сюда_случайную_строку_минимум_32_символа');
```
Сгенерировать: `php -r "echo bin2hex(random_bytes(32));"` — и никому не показывать, это ключ от всех сохранённых GitHub-токенов.

**2. SQL:** залить `sql/migrations/018_github_deploy.sql`

**3. Права на запись:** создать папку `services_data/` в корне проекта с правами на запись от PHP (755 или 777 в зависимости от хостинга) — туда распаковываются задеплоенные сайты

**4. Расширение ZipArchive** должно быть включено в PHP (`php -m | grep zip`) — на InfinityFree обычно есть из коробки, но стоит проверить в панели хостинга

## Честно про ограничения — не обманываю с "5 минут и всё готово"

- **Деплоится только уже готовый статический сайт** (HTML/CSS/JS в корне репозитория или собранный React/Vue билд, закоммиченный в git). Если у пользователя в репозитории только исходники и `package.json` с `npm run build` — так это не задеплоится, деплой упадёт с понятной ошибкой "index.html не найден"
- Причина: InfinityFree и подобный бесплатный PHP-хостинг физически не может запускать `npm install && npm run build` — там нет Node.js и shell-доступа. Настоящий "как Vercel" билд с произвольным стеком нужен либо на VPS с Node, либer через GitHub Actions в репозитории пользователя (собрать в CI и запушить готовый `dist/` в отдельную ветку, а деплоить уже её) — это отдельная, более сложная задача
- **Деплой синхронный** (в рамках одного HTTP-запроса) — для больших репозиториев может упереться в лимит времени выполнения PHP на хостинге (`max_execution_time`). Для типичных небольших статических сайтов работает нормально
- Сервисы всех пользователей физически лежат на одном домене (`services_data/`) — я закрыл iframe через `sandbox` без `allow-same-origin`, чтобы чужой JS не мог украсть куки твоего сайта, но по-хорошему для полной изоляции такие вещи выкладывают на отдельный поддомен (например `apps.твой-домен.ru`) — это можно добавить позже, когда будет wildcard-поддомен на хостинге
