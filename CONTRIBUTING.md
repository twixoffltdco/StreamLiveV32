# Правила участия

Спасибо, что хотите помочь проекту! Ниже — как это сделать, чтобы Pull Request приняли
быстро и без правок.

## Перед тем как начать

- Для мелких правок (опечатки, мелкие баги) — можно сразу открывать PR.
- Для новых модулей/фич — сначала откройте Issue с описанием, что и зачем добавляете,
  чтобы не делать работу впустую, если направление не подойдёт.

## Требования к коду

- Чистый **PHP + MySQL/MariaDB**, без Composer-зависимостей — проект должен разворачиваться
  на обычном shared-хостинге (InfinityFree и подобных) без SSH и без возможности ставить
  пакеты.
- Каждый добавленный/изменённый `.php`-файл обязан проходить `php -l` без ошибок.
- Изменения схемы БД — **только через миграции** в `sql/migrations/`, пронумерованные по
  порядку (следующий свободный номер), и обязательно отражены в `sql/schema.sql`.
  Не трогайте существующие миграции — только добавляйте новые.
- Настройки — через таблицу `settings` (`key`/`value`, `get_setting()`/`set_setting()`),
  не через хардкод.
- Таблицы, которые создаются в рантайме (self-healing по паттерну `..._ensure_table()`),
  оборачивайте `CREATE TABLE`/`ALTER TABLE` в `try/catch` — на части бесплатных хостингов
  у пользователя БД нет прав `CREATE`/`ALTER`, и необработанное исключение кладёт 500 на
  каждый заход.
- Красивые URL без `.php` — ссылки, `<form action="">` и `fetch()` в новом коде должны
  указывать на чистый путь (`/videos`, а не `/videos.php`) — `.htaccess` сам подключает
  нужный файл.
- Не ломайте существующую функциональность — если правите общий файл (`functions.php`,
  `header.php`, `antibot.php`), проверьте, что затронутые страницы по-прежнему открываются.

## Что не принимается

- Изменения, требующие Node.js/Python/другой рантайм на сервере (кроме отдельных
  GitHub Actions-скриптов, если они не часть самого сайта).
- Правки, ломающие обратную совместимость БД без миграции.
- Код без тестирования — как минимум `php -l` на все изменённые файлы и ручная проверка,
  что страница открывается и не роняет остальной сайт.

## Оформление PR

- Короткое описание: что изменилось и зачем.
- Если меняли схему БД — укажите номер новой миграции.
- Если это фикс бага — как воспроизвести баг до фикса (по возможности).
